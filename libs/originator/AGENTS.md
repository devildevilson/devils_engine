# originator — рабочая карта

Документ для агента, который правит эту библиотеку. Человеку — `README.md`: там устройство и
объяснения. Здесь только то, что нужно, чтобы ПРАВИТЬ и не сломать: где что лежит, чего нельзя
нарушать, как делаются типовые правки и чем это проверяется.

Общий контекст проекта — `AGENTS.md` в корне репозитория. Контекст переноса на GPU —
`ORIGINATOR_GPGPU.md`.

## 2. Инварианты

Нарушение любого из них — дефект, даже если тесты зелёные.

1. **Апертура объявляется инструментом, параллельность выводится.** Не добавлять API, которым скрипт
   сообщает «это можно параллелить».
2. **Проверка идёт ДО исполнения** и называет шаг, инструмент/номер элемента и поле. Падение на
   середине очереди недопустимо.
3. **Один способ выложить push-байты:** `device_call_header` + параметры по одному `float`. Второй
   шапки не заводить (она уже была и разъехалась).
4. **Одна семантика записи значения:** `store_component` для числового пути, `store_integer` для
   wide integer. Любой другой путь (в том числе перевод в GLSL) повторяет соответствующий зажим
   и усечение; wide integer нельзя пропускать через double.
5. **Быстрый путь только при точном совпадении рода**, не размера.
5a. **Копия на устройстве — КЭШ, и она вправе быть ШИРЕ истины.** Узкий род живёт там 32-битным, а
   преобразование на границе делают те же `load_component`/`store_component`, что и на хосте. Не
   заводить второго правила преобразования: расхождение путей обязано быть невыразимым, а не
   маловероятным. Зажимает шейдер, по границам ИСХОДНОГО рода (`device_store_range`) — поле из
   `resident` не скачивается никогда.
6. **Один хеш на движок:** `utils::shared::prng2` / `utils::prng`. Свой splitmix в новом коде — дефект.
   Копия хеша в преамбуле шейдера существует только потому, что у compute-программы нет `#include`, и
   она сверяется тестом.
7. **`run_script` принимает только `devils_script`.** `translated_form` выдаёт исключительно
   транслятор (ключ `translation_authority`).
8. **Где считается очередь — объявление конфига.** Не добавлять «умный» выбор пути по наличию
   устройства: молчаливый переход на CPU меняет мир под тем же зерном.
9. **Результат не зависит от разбиения работы.** Побитовое равенство «параллельно == последовательно»
   и «слито == не слито» проверяется тестами; всякая новая схема обязана его сохранить.
10. **Результат чанка — функция (зерно мира, ключ чанка).** Никаких переносов состояния между чанками.
11. **Отказ несёт причину.** Ни одного `return {}` там, где вызывающий не сможет отличить «нет» от
    «нельзя, и вот почему».
12. **Ядро не тянет чужие зависимости** (см. цели сборки выше).
13. **Инструмент объявляет свою ВРЕМЕННУЮ память** (`footprint`), и «ничего» объявляется так же явно,
    как «столько-то»: `no_temporary_memory`. Молчание означает НЕИЗВЕСТНО и попадает в отчёт по имени.
    Оценка обязана быть ВЕРХНЕЙ — занижать стоимость памяти нельзя.
14. **Ключ производителя в цепочке — проекция своего ключа или ДАННЫЕ ранней связи.** Не регистрировать
    функции ключа на стороне хоста: правило «что с чем связано» тогда уходит из данных в C++.
15. **Коробка влияния формы — обещание: вне неё значение не ниже оценки фона.** Сужать коробку ради
    скорости нельзя — отсечение перестанет быть точным, и поле начнёт зависеть от области.

## 3. Рецепты

### Добавить нативный инструмент

1. Тело и `tool_description` — в файл своего набора (`standard_tools.cpp` и т.д.). Апертура выбирается
   по тому, КАК инструмент адресуется, а не по тому, как удобнее.
2. Читать поля через `tool_call::input/output`, форму — через `resolve_extent`, параметры — через
   `call.params->number(...)` с тем же default'ом, что попадёт в `device_params`.
3. Необязательные входы/выходы объявляются числами `optional_inputs`/`optional_outputs`, а тело
   спрашивает `has_input`/`has_output`, а не считает размер списка.
4. Зарегистрировать в соответствующем `tool_registry::add_*`.
5. Тест в `subprojects/tests/originator_tools_test.cpp` (или по набору): результат + «1 поток ==
   N потоков побитово».
5a. Объявить `footprint`: считать по тем самым таблицам, которые тело заводит, ВЕРХНЕЙ оценкой. Ничего
   не заводит — `.footprint = no_temporary_memory`, а не молчание.
6. Строку в таблицу инструментов `README.md`.

### Дать инструменту устройственную форму

1. Написать `device_body` ПРОТИВ АКСЕССОРОВ (`in_0_at(index)`, `out_0_set(index, value)`), без
   `layout(...)` и без своей push-шапки. Индекс элемента уже есть, охранник по `count` уже стоит.
2. `device_params` — те же имена и те же default'ы, что читает тело на CPU; `symbol`, если имя занято
   в GLSL (`min`, `max`).
3. `device_filtered_inputs` — только для входов, которые читают МЕЖДУ элементами: это единственное,
   из чего выводится картинка.
3a. Не умещается в выражение — функции идут в `device_prelude` (внутри `main` их не объявить), а число
   компонент привязки тело спрашивает у `ORIGINATOR_IN_<i>_COMPONENTS`, а не угадывает.
4. `device_integer_ready` нужен только телу над ШИРОКИМ целым (`ui`/`i`): узкие роды точно
   представляются во `float32` (предел 2^24), и это решает `exact_in_float`, а не объявление.
5. `order_free_writes` — только целочисленное накопление; плавающее объявить так нельзя.
6. Параметров не больше `device_param_limit` (27): предел push-константы ОБЪЯВЛЕН библиотекой в 128
   байт — гарантированный минимум Vulkan, — и `maxPushConstantsSize` не спрашивается нигде.
7. Параметр-СЛОВО (`metric = "chebyshev"`) кладётся через `device_param::resolve` — функция от
   `parameters` к числу. Числовой синоним заводить нельзя: это второй способ сказать то же самое.
8. Подготовленного на хосте индекса на устройстве НЕТ: тело собирает нужное из тех же привязок, из
   которых его собирает подготовка (см. `polyline_distance`).
9. Тела может не быть ПО ПРАВУ — но отказ обязан быть ИЗМЕРЕН и записан комментарием у инструмента
   (см. `sphere_points`: `0.9955` оборота расхождения на миллионе точек). И «тела нет» — НЕ ОДНА
   причина: `sequential` не пускается апертурой (это `refused`), а `scatter`, строящий CSR, требует
   ТРЁХ проходов (счёт, префиксная сумма, заполнение), а не тела. Прежде чем писать — посмотреть
   апертуру.
9a. Хеш шире 32 бит собирается из пары `uint` через `umulExtended` (см. `value_noise`), а сырое
   64-битное зерно берётся из `raw_seed_lo`/`raw_seed_hi` — свёрнутое `seed` необратимо. Сверять
   такое тело надо там, где между хешем и результатом НЕТ плавающих операций, иначе проверяется
   арифметика драйвера, а не хеш.
10. Тест в `originator_device_queue_test.cpp`: сверка с CPU-путём.

### Добавить конструкцию в транслятор `ds` -> GLSL

1. Понять форму узла в AST: `=`/`?=`/пустой оператор — это ВЫЗОВ, блоки приходят объектами, пути вроде
   `ctx:arg:x` — одним `unrecognized` токеном.
2. Ветку добавить в `translator::call` (или в `value` для голого идентификатора). Переводить
   ПОДВЫРАЖЕНИЯ строго ВПЕРЁД, отдельными операторами: перевод попутно нумерует аргументы
   push-константы и соли случайности.
3. Если конструкции нужна именованная величина — класть её локалью через `temporary`/`declare`, а не
   повторять выражение. Локаль вычисляется ДО ветвления: запись изнутри ветки обязана отклоняться
   (`branch_depth`).
4. Арифметика ВСЕГДА плавающая: у `ds` в программе `originator` чтение поля — это `double`, поэтому
   целочисленная арифметика в шейдере с ним РАЗОЙДЁТСЯ. Целым остаётся ЛИСТ (целый литерал, чтение
   поля целого рода) — в сравнениях и в записи-тождестве, ради потолка `float32` в 2^24.
5. Если перевести нельзя — строка в `refusals` со СВОЕЙ причиной.
6. Тест в `originator_translate_test.cpp`: форма текста + побитовая сверка с CPU на ЦЕЛОЧИСЛЕННОЙ
   программе (на плавающей пути расходятся законно).
6. Обновить список переводимого в `script_translate.h` и в README.

### Добавить поле в общую шапку push-константы

Правятся ТРИ места, и все три обязаны совпасть: `device_call_header` (`tools.h`), строка шапки в
`build_device_shader` (`device_form.cpp`) и заполнение в `device_queue::write_push`. Комментарий с
байтовой раскладкой в `script_translate.cpp` — четвёртое. Тесты, собирающие push вручную, используют
саму структуру, поэтому чинятся сами.

### Добавить биндинг lua

Только СВОБОДНОЙ ФУНКЦИЕЙ или методом `script_host`, никогда лямбдой (см. ловушки). Ярлык с
привязанным именем — замыканием в lua (`install_shortcuts`). Новое имя в `originator` не должно
совпасть с `reserved_api_names`.

### Добавить набор инструментов

Новый `.cpp` в `src/originator`, метод `tool_registry::add_*_tools()`, файл-блок с объяснением, ПОЧЕМУ
набор отдельный (по способу адресоваться или по контракту, а не по теме), строка в `CMakeLists.txt`.

## 5. Ловушки

- **sol2 и лямбды.** Две лямбды с одинаковой сигнатурой в одной функции делят метатаблицу `__gc` —
  порча памяти, падающая далеко от места ошибки. Биндинги объявлять функциями.
- **Порядок перевода.** Порядок вычисления аргументов одного вызова в C++ не определён; собранный
  as-is список аргументов зависел бы от компилятора.
- **Равенство в `ds` — с допуском** (`1e-6`), а не побитовое. Перевод обязан повторять ту же константу.
- **`as_span<T>` над чужим родом** молча пишет биты. Проверять род, не размер.
- **64-битные целые (`ul`/`l`) через double теряют биты выше 2^53.** Любое копирование «значение
  поля в значение поля» (обрезка, `lookup`, будущие инструменты) идёт байтами или `get_integer`/
  `set_integer`. Обрезка цепочки однажды так скруглила ключи узлов, и это видно было только по
  разошедшимся станциям.
- **Форма документа `tavl`.** Строка `values = ...` рядом с блоком верхнего уровня превращает документ
  в структуру, и он читается не тем обходом, БЕЗ ошибки. Разделителей `//---` в точке входа быть не
  должно.
- **Разделитель строк в `tavl`** — запятая или перевод строки; пробел не разделяет.
- **Случайность на устройстве не равна CPU** (соль `ds` живёт в скомпилированном контейнере, хеш на
  GPU 32-битный). Не «чинить» это сверкой значений: сверять надо повторяемость и формулу на хосте.
- **Прогон на ноутбуке меряет тепло.** Замеры — отдельным режимом, варианты чередуются, читать медиану.
- **Поле с коробками не непрерывно.** Коробка заливки обрывает форму в глубине воды, коробка выреза —
  в толще породы: поле там скачет между значениями одного знака. Обещание наклона (`slope`) и пропуск
  блоков поверхности поэтому ведутся по полю, обрезанному полосой `band`; без полосы честный наклон
  ловит проверка соседних углов на первом же камне в воде.
- **Demiurg views/pointers** требуют стабильного registry. `view<T>::operator[]` сейчас возвращает
  `T*` по значению; прежняя запись о возврате висячей ссылки устарела. Через clear/reparse хранить handle.

## 6. Соглашения

- **Комментарии по-русски**, как и во всём проекте. ИСКЛЮЧЕНИЕ: текст, который уезжает наружу —
  сгенерированный GLSL, сообщения об ошибках трансляции, — по-английски: его читают glslc, отладчик и
  люди вне проекта.
- **У каждого файла блок сверху**, после `#include` и до `namespace`: что это, на что обратить
  внимание, особенности реализации. Длинные объяснения живут ТАМ, а не над отдельной декларацией.
- **По коду — только заметки по делу:** описание алгоритма над функцией и короткие пояснения
  особенностей. Копна комментариев над одной декларацией — повод перенести её в блок файла.
- **Комментарий объясняет ПОЧЕМУ, а не что.** «Считаем сумму» — мусор; «сумма идёт в порядке чанков,
  иначе результат зависит от числа потоков» — по делу.
- **Числа в документации — измеренные.** Если числа нет, писать, что его нет, а не оценивать.
- Порядок полей структур — по убыванию размера/выравнивания.
- Не `std::map`: `std::vector` или `gtl::flat_hash_map`.

## Актуализация 2026-11-07

- Pipeline/queue остаются самостоятельными API: не переносить все лаборатории на chain ради формы.
- `script_column.h` уже реализован: third consumer DS AST, VM fallback имеет отдельный контракт.
  `select`/`value_or` вычисляют обе ветви; не переносить побочные эффекты в pure pointwise путь.
- DS-вызов с круглыми скобками может быть операндом выражения (`sqrt(x) - 1`); прежний запрет
  относился к форме `f = { ... }`. Элементы разделяются запятой или переводом строки.
- `shapes` в документе chain и `add_script_kind` позволяют задавать формы через DS.
  CPU wide kinds `d`/`ul`/`l` не требуют побитового совпадения с GPU и устройством отвергаются.
- Роли natural/fill/cut и blend меняют composition поля; коробки влияния должны учитывать blend.
- Decoded rows/views строятся без удержания instance lock и повторно проверяются при insert:
  decoder может запросить view того же instance. Owning field handle нужен memoized sampler.
- Cross-thread cycles chain недопустимы; same-thread cycle detection не доказывает отсутствие
  межпоточного deadlock. Не добавлять внешний scheduler поверх parallel fan-in/helping waits.
- Смена миров GN09 исторически разрешила изменение seed result; это не отменяет детерминизм
  одного описания и независимость от порядка чанков. Обещания мира GN09 — в его README.
- Новая очередь — [TASKS.md](../../TASKS.md), аудит — [PROJECT_AUDIT.md](../../PROJECT_AUDIT.md).

## Технический аудит 2026-11-07

256 МиБ RAM — диагностический ориентир, допустимый бюджет задаёт проект.
8 аппаратных потоков — минимум машины, а не верхний предел потоков процесса. Cache capacity/trim/footprint по отдельности не ограничивают весь heap.
F-02 исправлен: script_host устанавливает critical-error policy и проверяет latch после
защищённых вызовов. utils::critical_error доходит до host даже через pcall/xpcall/coroutine.

новый scheduler поверх tools/chain. См. TECHNICAL_AUDIT.md и TECH-02/03/11.

## Владение execution state

Production TLS отсутствует. `generation_context` передаётся chain get/resolve/build и step/tool
calls; native nested вызов передаёт `run.context()`. Один context эксклюзивен, его можно передать
другому worker только между вызовами. Root overloads без context берут chain-owned slot;
`release_contexts()` после drain уничтожает slots, а не кэш результатов.
Lua hosts принадлежат context, не OS thread. Внешний context освобождать до удаления chain,
поскольку consumer tools могут захватывать chain по ссылке. `context.release()` уничтожает hosts
и scratch при живых workers. Parallel native tool jobs получают свой context с отдельным scratch.
`column_program::run` требует `column_workspace&`, `run_once` — одноразовый вариант.
Повторные point queries используют `field_workspace&` либо sampler; default overload создаёт
временный scratch. Вложенный query получает стабильный frame, не перезаписывает scratch parent.
Не двигать/не release активный workspace. Карта и проверки —
[review](../../docs/review/LIFETIME_AND_RESOURCES.md).

## Общая механика GN (P2)

- `graph_walk.h`: общий CSR builder, weighted walk, FIFO BFS/predecessors; caller-owned scratch.
  Порядок BFS — порядок adapter arcs, weighted ties — distance/label/node/previous.
- `components` сохраняет existing labels; CSR offsets покрывают execution range, не всю
  spare capacity values. Не возвращать зависимость scratch от raw sparse label.
- Generic CSR blur/frontier/slope/vote и graph_* используют один GLSL emitter.
  `device_min_inputs` запрещает применять CSR форму к stencil варианту; stencil пока CPU.
- `run_script` умеет component inputs, program groups, param_*; `gather_script` — отдельная
  read-only own/other регистрация. Не разрешать output alias neighbour inputs/topology.
- Pure DS получает column form; refusal из try_compile — данные, critical error не fallback.
  VM-vs-column tests компилируют независимый VM через script_backend::virtual_machine.
  Saved slots/lists принадлежат элементу/кандидату, не chunk: clear перед каждым evaluation.
  script_footprint возвращает optional bytes; dynamic lists → nullopt/unknown, не нулевой scratch.
- Small-set Lua algorithms встроены из `src/originator/algorithms.lua` при CMake configure;
  доступны как originator.algorithms. Rules/profile/bounds остаются у consumer.
  Никаких тайных heaps на OS thread; propagate требует явный visit budget.
- [Контракты и evidence](../../docs/review/P2_ORIGINATOR_MIGRATION.md). Проверять native formula
  oracle, queue refusals, GLSL compile без GPU и GN package bytes отдельно от campaigns.
