# GN09 — потоковый подводный мир

**ЗАКРЫТА 2026-11-13** закрывающим аудитом: см. «[Аудит при закрытии](#аудит-при-закрытии)» в конце.

Площадка исследует, можно ли собрать из `libs/originator` большой потоковый мир, у которого все
правила лежат в тексте (TAVL/Lua/DS), а C++ только загружает цепочку, проверяет и показывает
результат. Мир — подводные пещеры для лодки 34 × 12 м и вылазок пловцов: нерегулярные биомы,
сеть главных узлов с маршрутами, естественный рельеф с грядами и обвалами, аванпосты в породе у
каждого главного узла и независимые экспедиционные пещеры. Чанки появляются вокруг движущейся
камеры; карта мира заранее не строится.

Ответ площадки — да. Собственных нативных правил у GN09 нет; всё, чего не хватало (цепочка
генераторов, поле из форм с ролями, локально уточнённая поверхность, рамки и наклоны форм, клетки
Куна), стало общими механизмами `originator`. Поток выдерживает полёт 48 м/с на шести работниках.
Естественность формы остаётся предметом визуальной оценки автора; проверки её не доказывают.

Как устроен генератор — [GENERATOR.md](GENERATOR.md). Прежний генератор площадки (`resources/gn09`,
цели `GN09_local_adventure*`) удалён при закрытии; он есть в истории git до коммита `86b981a`
включительно. Имена `GN09_next` и `gn09_next` остались от времени, когда генераторов было два.

## Сборка и запуск

Из корня репозитория:

```sh
cmake --build build-release --target GN09_next GN09_next_viewer -j 8
BIN=./build-release/subprojects/playgrounds/GN09_local_adventure/bin

$BIN/GN09_next --verify --seeds=20                 # полная проверка seed 0–19 (~4 мин)
$BIN/GN09_next --map=/tmp/gn09_map.svg --plans=/tmp/gn09_plans.svg
$BIN/GN09_next_viewer                              # интерактивный полёт
```

Консольная программа `GN09_next` без ключей проверяет один seed. Ключи:

| Ключ | Что делает |
| --- | --- |
| `--verify`, `--seeds=N` | полная проверка seed `--seed` … `--seed+N-1` |
| `--verify-caves`, `--verify-outposts` | только пещеры / только аванпосты; при `--seeds=1` аванпосты печатают построчный отчёт |
| `--map=F.svg` | карта биомов, сети и аванпостов |
| `--plans=F.svg`, `--outpost-gallery=F.svg` | план и разрез трёх аванпостов / планы всех девяти аванпостов seed |
| `--cave-plan=F.svg --sector=X,Z --cave-layer=L` | схема пространств одной пещеры в проекциях XZ/XY |
| `--flight=48 --seconds=20 --workers=6` | приёмка потока без отрисовки; код 2 — были кадры с неготовым ближним кубом |
| `--bench` | блок 8×5×7 чанков в одном потоке: стоимость шагов и отпечаток всех вершин |
| `--outpost-chunks` | стоимость чанков, задевающих аванпосты |
| `--natural`, `--caves-only` | цепочка без аванпостов и пещер / только пещеры |
| `--progress` | статистика стадий каждые 5 с во время длинной проверки |

`--sector=X,Z` — адрес главного узла (шаг 384 м); в видах пещер — адрес системы (шаг 480 м).

### Просмотрщик

```sh
$BIN/GN09_next_viewer --natural --view=gallery     # биомы: gallery, clutter, hall, ocean
$BIN/GN09_next_viewer --view=collapse              # завал под повреждённым потолком
$BIN/GN09_next_viewer --view=station-dock --clear --radius=4 --sector=1,0
$BIN/GN09_next_viewer --view=station-exterior      # наружная стена аванпоста из воды
$BIN/GN09_next_viewer --view=station-room          # стыковочный отсек изнутри
$BIN/GN09_next_viewer --view=cave --clear --radius=3                # вход пещеры в полном мире
$BIN/GN09_next_viewer --caves-only --view=cave-hall --clear --radius=3  # также cave-shaft, cave-tight
```

`--view` ищет подходящее место около `--sector`. Полезные ключи: `--clear` — служебный свет и слабая
мутность для осмотра формы; `--diagnostic` — цвета нормалей; `--radius=2..8` — окно (по умолчанию 4,
то есть 9³ чанков); `--position=X,Y,Z --yaw --pitch` — точная камера; `--frames=N --dump=F.ppm` —
воспроизводимый кадр; `--speed` — скорость камеры. В окне: WASD/QE — движение, мышь — взгляд,
Shift — ускорение, M — режим изображения, G — границы чанков, U — оверлей, N — другой seed,
Esc — выход. Без `--frames` просмотрщик работает, пока его не закроют.

## Проверки

| CTest | Команда | Время |
| --- | --- | --- |
| `GN09_next_smoke` (`gn_smoke`) | `GN09_next --verify --seed=7` | ~10 с |
| `GN09_next_caves_smoke` (`gn_smoke`) | `GN09_next --verify-caves --seed=7` | секунды |
| `GN09_next_verify` (`gn_campaign`) | `GN09_next --verify --seeds=20` | ~4 мин |
| `playground_cli_migration_contract` | разбор ключей обоих исполняемых файлов | секунды |

`--verify` проверяет: согласованность биомов при разных размерах запроса и с DS-маской; непрерывность
профиля галереи; подъём океанского дна к краю; каноническое владение рёбрами, связность и N на
кратчайших путях; проход лодки по маршрутам; заглубление опор и то, что защищённая вода не
перерезает выступы; размещение аванпостов (док, граф отсеков по реальным проёмам, маяк и устье шлюза
в воде, пределы габарита); графы пещер, габарит пловца в узком ходе и отсутствие сетки, запирающей
ход; повторную сборку по ключу; швы чанков по значениям поля на общей грани.

Это геометрические пробы с запасом, а не симуляция движения лодки или пловца, и не доказательство
естественности формы. Библиотечные механизмы, на которых стоит площадка, проверяют
`originator_surface_test` и `originator_field_test`.

## Производительность

Release, машина разработки (12 потоков), `surface_kuhn = 1` с пропуском блоков и нормалями из
решётки — настройки `constants.tavl` по умолчанию. Приёмка — `GN09_next --flight=48 --seconds=20
--workers=6`: полёт без отрисовки по X от узла 0,0 seed 0, окно 9³, опережение 6 слоёв, ближний
куб 5³; на 48 м/с нужно ~243 чанка/с.

| Показатель (2026-11-13) | Значение |
| --- | --- |
| Кадры с неготовым ближним кубом | 0 / 1199 |
| Холодная загрузка ближнего куба | 4,1 с |
| Чанков за 20 с полёта | 5476 |
| `landscape`, собственное время чанка в полёте | 5,6 мс |
| `field_surface` в полёте | 3,95 мс |
| Средняя сборка чанка с ожиданиями | 10,0 мс |
| `--bench`: вершин, отпечаток | 1 265 994, `385282cbb3275818` |
| `--natural --bench`: вершин, отпечаток | 855 948, `fbe0f066e36d3174` |

Отпечаток `--bench` меняется только при изменении геометрии или нормалей: правки, которые
обещают тот же мир, обязаны его сохранить. Что осталось заметным: галереи (`terrain/01_galleries.lua`)
— чистый Lua, около 25 мс на владельца; на точку поля приходится ~11 отрезков галерей; ожидание
чужой сборки аванпостов и рельефа приходится на холодный старт и вход в новые узлы. Уточнение стыка
аванпоста с породой (`outpost_crease_refinement`) добавляет вершинам породы в чанках у аванпостов
45–60% (замер до клеток Куна).

## Решения автора и границы

- **Аванпост у каждого главного узла; отказ — ошибка** с ключом узла и счётчиками причин. Один тип
  ядра (метка `core`), один масштаб. Оформление позже: маяк — только точка в данных.
- **Пересечения аванпостов с пещерами игнорируются**: без правил избегания и без отбраковки.
- **Пещеры — не приключение с гарантиями.** Нет обязательной длины, глубины, толщины массива,
  изоляции, длинного возвращения, запрета лодке, бюджета воздуха или времени. Обнаружимый вход не
  гарантирован. Ресурсов, существ, маркеров и целей нет.
- **N — гарантия графа, не маршрута**: в открытой воде промежуточные узлы можно обойти. Пересечения
  естественных полостей разрешены.
- **Поверхность — клетки Куна** (`surface_kuhn = 1`, принято автором после осмотра): вдвое меньше
  вершин, чем у разбиения через центр клетки, тени и силуэты чуть мягче. Без них полёт 48 м/с на
  этой машине не проходит.
- Сокращение числа отрезков галерей на точку поля автор счёл ненужным.

## Не сделано

- Отложенные композиции рельефа: слоистые уступы и террасы, косые разломы, естественные арки и
  перемычки, наклонные осыпи, разрушенные многоярусные галереи. Их задавать отдельными формами,
  связанными с маршрутом, а не амплитудой общего шума.
- Хобот без изгибов; межстанционных туннелей нет; поза «док над ядром» почти не даёт башен (башня
  стоит на дне, где проходит защищённая вода узла) — это следствие правил, не дефект.
- Предметы, оборудование, существа, свет как настройка рендера, разрушение, физика воды, связь,
  сонар, задания.
- Столкновения тела и управление пловцом в просмотрщике: камера свободная.

## Аудит при закрытии

2026-11-13, вместе с удалением прежнего генератора и уборкой стиля. Аудит нашёл десять пунктов: семь
закрыты, три оставлены сознательно — их решение принадлежит библиотеке или общему просмотрщику.

**1. `--natural` строил поверхность другим путём (настоящий дефект).** Полная цепочка шла через
`field_surface` с клетками Куна, а `natural_landscape` (у него нет связей с пещерами) — через старую
ветку `marching_tetrahedra` по разбиению через центр клетки: вдвое больше вершин, другие нормали.
Вид «мир без аванпостов и пещер», которым оценивают естественный рельеф, показывал не ту поверхность,
что полный мир. Теперь у всех трёх чанковых генераторов один путь; ветка, выборка решётки и буферы
`samples`/`middles` убраны. Полный мир при этом не изменился: отпечаток `--bench` тот же.

**2. Комментарий о наклонах врал.** В `world.tavl` граница градиента шума была записана как
`3*sqrt(3)/period`, а код (`value_noise_slope`) объявляет `3/period`, найденную перебором. Неверный
комментарий подталкивал бы завысить наклоны при правке формы. Исправлен.

**3. Мёртвые данные.** Четыре константы (`node_radius`, `gallery_radius`, `clutter_radius`,
`outpost_dock_gap`), формула `field/03_rock.ds` и поле `O.entry_room` никем не читались — убраны.
Комментарии со ссылками на удалённые планы («stage 4 of NEXT_OUTPOST_PLAN.md», «placeholder core»)
переписаны под нынешнее устройство.

**4. Ключи без описаний.** У `GN09_next` 7 ключей и у просмотрщика 5 ключей в `--help` не имели
описания. Дописаны.

**5. Число работников по умолчанию.** `GN09_next --flight` брал 11 работников, просмотрщик и приёмка — 6.
Целевая машина — 8 потоков; по умолчанию теперь 6, как у приёмки.

**6. История в выводе и ошибках.** Проверка печатала «Verified active slice 2»; ошибка поиска формы
не называла имя (`unknown shape source`). Теперь: «Verified seed N: …» и `world.tavl has no shape kind
'<имя>'`.

**7. Стиль.** `constants.tavl` — одна константа на строку с пояснением; `world.tavl` и длинные
документы буферов разбиты по смыслу; Lua приведён к одному виду (пробелы вокруг операторов, один
оператор на строку, перенос длинных строк); C++ отформатирован с переносом по 120 столбцов, ёмкости
хоста — по одной на строку. Всё это проверено на неизменность: токены `.tavl` и Lua до и после
совпадают (у Lua — без учёта убранных `;`, ни один из которых не стоял перед `(`), отпечаток
`--bench`, построчный отчёт `--verify-outposts` и обе SVG (`--map`, `--plans`) совпадают побайтно.
Формулы DS не трогались: несколько строк в них длиннее 120 символов.

**8. Без потребителя после удаления прежнего генератора (оставлено).** На площадках больше не
вызываются инструменты `originator` `exclusion_set`, `propagate`, `quarter_voxel_mesh`,
`segment_box_distance`, `tree_distance`, `skeleton_distance`, `skeleton_tour` и `marching_tetrahedra`.
У последнего не было и прямого теста; после закрытия он появился в `originator_volume_test` и сразу
нашёл несогласованный обход треугольников (исправлен в библиотеке). В `common/chunk_viewer` отладочные линии (`line_provider`) никто не
передаёт. Удалять или покрывать тестами — решение по библиотеке и общему просмотрщику; инвентаризация
(`scripts/inventory_originator_tools.py`) обновлена.

**9. Пустой кадр вида биома (оставлено).** `--view=gallery` ставит камеру в центр узла и не выбирает
направление; у seed 0 в просторной галерее кадр без `--pitch=-0.4` почти пуст. Это вид для осмотра,
а не ошибка мира.

**10. Наклоны форм — обещание, а не доказательство (оставлено).** Пропуск блоков опирается на
объявленные `slope`; заниженный наклон ловит проверка соседних углов громкой ошибкой, но только в
тех блоках, что всё же посчитаны. За полёт и кампанию она не сработала ни разу.
