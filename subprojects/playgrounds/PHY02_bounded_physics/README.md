# PHY02 — ограниченная память, пары и задачи Jolt

Headless-эксперимент с двумя сценами из коробок, сфер и составных форм. Площадка проверяет, можно ли на каждом тике собирать результаты запросов и поток контактов в пределах заранее подготовленной памяти. При равной сцене и входах результаты сравниваются целиком, по тикам, при `0`, `2` и `4` Jolt-воркерах. Вывод относится к этой площадке и закреплённой сборке Jolt.

Срез закрыт 2026-11-26. Профильные проверки прошли в Debug и Release, расширенная Release-сверка — на 512 динамических телах и 480 тиках. Адаптер к `atomic_pool` остаётся экспериментальным вариантом для сравнения.

## Запуск из корня

```sh
cmake --build build-release --target PHY02_bounded_physics -j 8
ctest --test-dir build-release -R '^PHY02_bounded_physics_' --output-on-failure
./build-release/subprojects/playgrounds/PHY02_bounded_physics/bin/PHY02_bounded_physics --verify --bodies=256 --steps=480
./build-release/subprojects/playgrounds/PHY02_bounded_physics/bin/PHY02_bounded_physics --scene=dense --bodies=256 --steps=480 --workers=4 --jobs=shared --pairs=hash --events=lanes --lookup=index
```

Обычный запуск измеряет одну конфигурацию. `--verify` проверяет обе сцены и матрицу вариантов. Размер сцены и число тиков берутся из CLI. Остальные параметры матрицы фиксированы. `--jobs=stock|shared` выбирает штатный пул Jolt или адаптер. `--pairs=linear|hash` выбирает кэш активных пар, `--events=shared|lanes` — буфер callbacks, `--lookup=linear|index|user-data` — преобразование `BodyID` в handle. `--workers` задаёт число Jolt-воркеров сверх вызывающего потока. В обоих вариантах есть один дополнительный воркер для независимой нагрузки. После физического шага общие воркеры могут использоваться для пакета запросов. У штатного пула Jolt в этой фазе работает отдельный движковый воркер.

## Контракты площадки

- Слоты, команды, пакет публикации и обратное отображение `BodyID` подготовлены заранее. Переиспользованный слот получает новое поколение. World token и sequence `BodyID` проверяются на соответствующих границах. Публикация готовит соответствие handle → `BodyID` до того, как Jolt может переставить пакет.
- Callbacks сохраняют идентичность пары форм и `added/persisted/removed`. Сбор дорожек получает общий резерв записей через атомарный индекс, поэтому одна занятая дорожка может использовать всю ёмкость. После одного дискретного шага события упорядочиваются по полному ключу. Кэш пары хранит прежнюю идентичность до удаления, даже при переиспользовании слота. Результат шага выдаётся только после проверки solver и буферов. Порядок нескольких подшагов и CCD выходит за пределы корпуса.
- Пакет использует собственный буфер на запрос и публикует результаты в порядке запросов. Различаются количество кандидатов, пересечения отдельных форм и уникальные цели. У луча равную дистанцию разрешает ID. Превышение лимита кандидатов или попаданий отказывает всему конкретному запросу. Буфер переиспользуется после потребления. Отчёт verify сохраняет копии для сравнения за пределами измеряемой фазы.
- Адаптер оставляет граф и барьеры в Jolt. `atomic_pool` исполняет ограниченное число pump-задач. Из них читается готовая очередь, ёмкость которой равна пределу живых Jolt jobs. Каждый готовый указатель держит ссылку до выполнения обёртки. Завершение шага дожидается и обёрток, чьи jobs раньше выполнил барьер. Проба заполняет очередь, исполняет её и проверяет добавление зависимой задачи в действующий барьер.

## Проверки и метрики

Сверка включает аналитические лучи и overlap, составную цель, равную дистанцию, пустой результат и отказ при превышении лимитов. Отдельно проверяются вход и выход из зоны, сон и пробуждение, удаление с активным контактом, повторное создание, продолжение после отказа команды, замена контакта при полном кэше, исчерпание event/cache/solver limits и диагностика исчерпания scratch в дочернем процессе. Проба кэша сравнивает удаление и повторную вставку при 32, 256 и 512 занятых местах из 512.

Отчёт показывает резерв памяти и пик scratch, занятость буферов и очереди адаптера, кандидатов и попадания, среднее время фаз, p50/p95/p99 тика и CPU на тик. Процесс считает вызовы C++ `new` и Jolt allocation hooks отдельно по подготовке, публикации тел, прогреву и установившемуся шагу. Счётчики показывают объём запросов на выделение и не измеряют RSS. Первые восемь тиков исключаются из сводки времени и проверок об отсутствии аллокаций в обвязке. Backend может выделять память внутри шага, его счётчик выводится отдельно. Сравнивать производительность следует повторными прогонами с одинаковыми параметрами, нагрузкой и лимитами.
