# frontier_online

Сетевой вариант [`tile_frontier`](../tile_frontier/): та же симуляция акторов (GOAP → FSM → анимация,
еда, хищники и добыча), но мир считает выделенный headless-авторитет, а графические клиенты
присоединяются к нему и показывают подтверждённый мир. Земля строится [`originator`](../../libs/originator/),
сеть — [`libs/network`](../../libs/network/). Своего netcode в проекте нет: рукопожатие, сессия,
транспорт, журнал тиков и повторный вход взяты из движка, проект добавляет только свои сообщения и
смысл канонических записей.

Карта правки — [AGENTS.md](AGENTS.md). Решения и разбор закрытия — [docs/review/FRONTIER_ONLINE_CLOSING_AUDIT.md](../../docs/review/FRONTIER_ONLINE_CLOSING_AUDIT.md),
байты протокола — [NETWORK_FRONTIER_ONLINE.md](../../docs/review/NETWORK_FRONTIER_ONLINE.md),
план устойчивости к враждебным участникам — [NETWORK_FRONTIER_ONLINE_PLAN.md](../../docs/review/NETWORK_FRONTIER_ONLINE_PLAN.md).

## Основные решения

- **Земля не едет по сети.** Чанк — чистая функция `(зерно мира, ключ чанка)`, обе стороны считают
  его сами. По проводу едут зерно, размер чанка, имя генератора и отпечаток его документов;
  рукопожатие сверяет отпечаток и корень пробного чанка.
- **Авторитет выделенный и headless.** Он линкуется только с причинным ядром, поэтому причинный код
  не может незаметно опереться на презентацию: такая зависимость ломает сборку сервера.
- **Клиент показывает последний проверенный тик**, без прогноза. Свой клик уходит предложением и
  появляется в мире, когда авторитет запишет его в канонический тик.
- **Обрыв — продолжение, а не конец.** Клиент возвращается тем же участником, пока авторитет держит
  его слот; мир клиента и неподтверждённые предложения переживают соединение.

## Запуск

```sh
# клиент: локальная симуляция
./frontier_online

# живая сессия: авторитет для людей (--play) и клиент
./frontier_online_server --live --play --listen=41236 --expect-joins=1 --ticks=36000
./frontier_online --join=SERVER_IPV4:41236          # --input-lead=N: свой клик на N тиков вперёд (1..32)

# снимок: кадр N в файл (.avif, .png или .ppm для отладки), выход с кодом 0 (записан) или 1 (не удался);
# --stay — снять и продолжить; в окне то же делает клавиша F12 (в <проект>/screenshots/)
./frontier_online --frames=120 --dump=frame.png

# headless-авторитет без сети: полная причинная симуляция
./frontier_online_server --ticks=600 --actors=512 --workers=4
./frontier_online_server --prefabs=prey,prey,prey,actor   # состав мира: i-й актор = cycle[i % size]
./frontier_online_server --paced --rate=60                # настоящий такт
./frontier_online_server --trace --ticks=120 > a.txt      # корень каждого тика (поиск первого расхождения)
./frontier_online_server --ticks=91 --dump=state.bin      # канонические байты состояния
./frontier_online_server --ticks=120 --verify             # контрактная проверка (в ctest)

# земля без окна: NxN чанков, корень, доли классов, диапазоны и децили сырых полей
./frontier_online_server --terrain=24 --world-seed=20260911

# присоединение без живой сессии: рукопожатие, мир, checkpoint, сверка корня
./frontier_online_server --listen=41400 --expect-joins=1 --timeout=30
./frontier_online_server --join=192.168.1.10:41400
./frontier_online_server --join=127.0.0.1:41400 --break-compat=protocol   # отказ обязан назвать причину

# процессный сценарий: авторитет и два headless-ведомых, у всех один итоговый корень
./frontier_online_server --live --listen=41236 --expect-joins=2 --ticks=1800 --timeout=120
./frontier_online_server --live --join=SERVER_IPV4:41236 --ticks=1800 --timeout=120
```

Мир сессии задаёт авторитет: `--world-seed`, `--extent=N` (бокс 8..1024, по умолчанию 64),
`--chunk-size`, `--generator`. `--resources=PATH` подменяет каталог модулей, но только внутри папки
проекта. `--listen=PORT` слушает все интерфейсы, `--listen` без порта берёт порт у ОС на петле,
`--live-loopback` — петля для CTest.

## Цели сборки

| Цель | Что это | Чем линкуется |
| --- | --- | --- |
| `frontier_causal` | причинное ядро: всё, что определяет состояние мира | только причинные библиотеки: ни painter, ни visage, ни sound, ни input, ни simul |
| `frontier_net` | сеть проекта (есть при `DEVILS_ENGINE_BUILD_NETWORK_GNS`) | `frontier_causal` + `network_gns` |
| `frontier_online` | графический клиент | `frontier_causal` + `devils_plane` (+ `frontier_net`) |
| `frontier_online_server` | headless-авторитет и ведомый | только `frontier_causal` (+ `frontier_net`) |

Без сетевого бэкенда клиент собирается и работает локально, `--join` отвечает отказом.

## Причинное ядро

- **Мир акторов** — [`actor_world_slice`](include/core/actor_simulation.h): ECS aesthetics, мозги
  GOAP/FSM из ресурсов `goap/`, `fsm/`, префабы из `prefab/`. Тик задаёт хост; шаг игрового времени —
  целая проекция фиксированного шага. Число акторов и состав — конфиг мира.
- **Хвост тика** — `tick_tail_reader`: читатель мира конца тика, который исполняется параллельно с
  построением kD-дерева следующего тика. Клиент кладёт туда [`actor_batch`](include/core/actor_batch.h)
  (кадр рендера), авторитет — ничего.
- **Цвет компонента** — [`color32`](include/core/color32.h): причинная величина (едет в checkpoint),
  байт в байт совпадающая с `instance_layout::rgba8_color`.
- **Корень состояния** — [`actor_checkpoint_digest`](include/core/actor_checkpoint.h): по каноническим
  байтам полного checkpoint плюс корни трёх секций (timeline / мир / счётчики), чтобы на расхождении
  первым ответом было «какая секция». Корень одинаков при 1/2/4/8 потоках и между Linux и Windows
  (CI сверяет трассу Windows с Linux-эталоном и печатает первый разошедшийся тик).
- **Правила времени** — константы [`world_rules.h`](include/core/world_rules.h): фундаментальные
  правила мира вшиты в проект, моды их не подменяют.

## Земля

[`terrain_source`](include/core/terrain.h) — пайплайн originator из
[`generator/world.tavl`](resources/modules/core/generator/world.tavl): шум → сглаживание →
классификация в код рельефа, тела шагов на lua. Генератор headless, поэтому авторитет считает ту же
землю, что и клиент. Клетка — `tile { terrain_code }`; текстуру выбирает клиент по палитре
`tile_textures` манифеста сцены (текстуры в порядке кодов). Запрос чанка самоописывающий: генератор,
зерно, размер чанка.

Пороги классификации в `values.tavl` — измеренные перцентили сырых полей (`--terrain` печатает
децили). Черта рельефа подобрана под размер окна (14 тайлов): при крупной черте на карту приходится
пара элементов рельефа. `terrain_source::fingerprint()` сворачивает зерно, размер чанка и тексты всех
документов генератора: правка порога меняет мир так же, как другое зерно.

## Сеть

### Присоединение

1. **Рукопожатие** (`libs/network`): совместимость проверяют обе стороны до единого байта
   состояния. `session_compatibility`:

   | поле | чем | что ловит |
   |---|---|---|
   | `protocol_version` | константа проекта (5) | другие байты на проводе |
   | `state_schema_fingerprint` | `actor_checkpoint_schema_fingerprint()` | другую форму документа состояния |
   | `content_root` | SHA-256 по файлам причинных каталогов `fsm`, `generator`, `goap`, `prefab` (обход реестра demiurg с учётом модов) | другие правила мира |
   | `intent_schema_fingerprint` | раскладка `spawn_food`, решётка, ревизия смысла записей | другую форму или смысл ввода |
   | `component_schema_fingerprint` | объявления `actor_position`/`actor_state` | другую форму компонентных образов |
   | `numeric_profile` | «родной float» | заявление, не гарантия |

   Каталоги `content_root` объявлены явно: у клиента и сервера разные деревья ресурсов. Пустой
   объявленный каталог — отказ, а не пропуск.
2. **Объявление мира**: параметры, по которым клиент посчитает землю сам; отпечаток генератора и
   корень пробного чанка сверяются.
3. **Checkpoint** — полное причинное состояние на тике K кусками (`network/document_chunks.h`) по
   объёмной полосе.
4. **Отчёт**: клиент сообщает корень загруженного состояния, сравнивает авторитет.

Отправка — не доставка, закрытие — не завершение: `try_send` только копирует в слот, а закрытие GNS
без linger. Поэтому авторитет закрывает отвергнутого с задержкой (`close_linger_ms`), чтобы причина
отказа дошла.

### Живая сессия

После подтверждённого отчёта авторитет шлёт канонические тики `canonical_tick_wire` по
упорядоченной полосе, ведомый исполняет их сам и сверяет корень на каждом тике. Ввод — предложения
`intent_batch` по ненадёжной полосе: номер ввода от 1 на сессию, до 16 неподтверждённых едут одним
пакетом и повторяются, авторитет держит окно дубликатов и окно тиков (не дальше 32 вперёд).

Каждый участник получает игрока `player_controller{peer}` канонической записью присоединения в
первом тике после подтверждения; уход — записью `peer_left`. Записи авторитета едут тем же конвертом,
что ввод, с зарезервированными номерами. На границе тика: присоединения, затем действия по
возрастанию peer, затем уходы. Смысл записей стережёт `player_intent_schema_fingerprint`.
Правило мира: пищи не больше четырёх норм (`food_target`); клик сверх предела записан в тик, но
эффекта не имеет — иначе участник по протоколу растил бы мир без конца.

### Повторный вход

После подтверждения входа авторитет выдаёт `reconnect_grant`: билет `network/credential.h`
(HMAC-SHA256, ключ случайный на процесс) и выведенный секрет. Обрыв, срок фазы и отставание за
историю держат слот участника `authority.hold_ms` (30 с): игрок стоит в мире без вводов и занимает
место в `max_peers`. Клиент возвращается рукопожатием с ключом и якорем (свой подтверждённый тик и
корень); авторитет догоняет его тиками из истории или снимком `checkpoint_ring` плюс тики после него.
Окно истекло или догнать не из чего — игрок уходит, клиент входит новым участником со свежим
checkpoint. Добровольный уход — словом `leave`; молча закрытое соединение — обрыв. Графический
клиент уходит словом при выходе и смене сцены (деструктор `net_client`).

Классы исходов на клиенте ([`net_client`](include/core/net_client.h), две машины
`network::reconnect_coordinator`): продолжают — обрыв, тишина, сроки фаз, отставание, рассинхрон;
входят заново — «авторитет полон», `unknown_session`; кончают сессию — несовместимая сборка,
расхождение мира, нарушения протокола, `shutdown`. Конец сессии не роняет процесс: окно остаётся с
последним проверенным миром, причина — в логе и в окне «network».

### Враждебные участники

Слоты освобождаются; сроки фаз со всех сторон; сообщение не своей фазы или полосы (в том числе
закрытое самим адаптером за нарушение контракта полос), неразбираемое предложение и поток
предложений больше учетверённой квоты за круг — нарушения, порог закрывает участника без удержания
слота. Пачка чуть сверх квоты (джиттер, заминка сервера) и записи сверх предела на тик только
отбрасываются: честный клиент повторяет и сам раздвигает свои клики по тикам. Квоты на участника;
последнее слово `session_terminated {reason}` называет причину. Ни один участник не роняет
авторитет: отставший за историю удерживается или отключается, переполнение журнала невозможно —
квоты считаются при приёме. Случайность рукопожатия, идентификаторы сессий и ключ билетов — CSPRNG
OpenSSL (`network/secure_random.h`).

### Сроки

`network.tavl` в папке проекта (необязательный): сроки ведомого, авторитета и повторного входа
клиента ([`network_settings.h`](include/net/network_settings.h)). Файла нет — умолчания.

## Клиент

- `--join=HOST:PORT` держит ведомого `live_follower` в кадре клиента: сетевой круг и исполнение
  тиков идут в потоке игрового фасада на его пуле, локальный мир сцены не создаётся. Мир сессии
  (земля, бокс) берётся у авторитета, а не из своей сцены; другой мир новой сессии перестраивает сетку.
- Окно «network» (`app.net_status()`): адрес, фаза (вход / в мире / возврат / конец), участник, тик и
  догон, игроки в мире, отставание, входы и возвраты, попытка, клики.
- Камера — движковый тип (`simul/camera.h`), объявлена в мире `worlds/frontier_online`; тайлы
  отбираются по объединению опубликованных камер (`simul::published_cameras`).
- Снимок — движковый механизм: условный пасс `capture` рендер-графа копирует цель кадра, байты
  забираются после fence кадра, поток ассетов кодирует AVIF, PNG или PPM (отладка).

## Ресурсы и настройки

| Папка | Что |
|---|---|
| `bin/` | исполняемые файлы |
| `cache/` | создаётся при работе: SPIR-V, кэш пайплайнов |
| `resources/engine/` | неизменяемое состояние движка: шейдеры, рендер-граф |
| `resources/modules/core/` | ресурсы проекта: миры, сцены, мозги, префабы, генератор, UI, текстуры, звуки |
| корень проекта | `settings.tavl`, `debug.tavl`, привязки клавиш, `network.tavl` |

Сцена объявляет мозги и префабы каталогами (`id = "fsm/"`, `prepare = true`): их грузит состояние
загрузки, загрузчик мозгов только проверяет готовность. Рендер-граф общий с tile_frontier и тестами
(`subprojects/tests/test_render_config`).

## Поставка

`frontier_online_package` — продукт: клиент и сервер рядом в `bin/` с общим `resources/`
(сервер читает только `resources/modules`); общие библиотеки обеих частей обязаны совпадать побайтно. `frontier_online_headless_package` и
`frontier_online_client_package` — части по отдельности. Пакет несёт все разделяемые библиотеки,
кроме glibc (`RPATH=$ORIGIN`; на Windows — DLL vcpkg и рантайм MSVC).

CI (ветка `ci`): `frontier_online-linux-baseline` (без AVX, для серверов; проверяется под
`qemu-x86_64 -cpu qemu64`), `frontier_online-linux-avx`, продукт `package-linux-product` (клиент avx +
сервер baseline), `frontier_online-windows`.

## Границы

- Прогноза своего ввода нет: клиент показывает подтверждённый мир с задержкой туда и обратно.
- Личности нет: авторитет принимает только пустое удостоверение («аноним»).
- `tile_grid` — конечная сетка с началом в `(0,0)`; стримингу во все стороны нужно окно чанков вокруг
  наблюдателя с координатами относительно чанка камеры.
- Сглаживание высоты на краю чанка не видит соседа (один ряд клеток при radius = 1); честная починка
  — считать чанк с полями шире нужного.
- Авторитет землю не материализует: актёры с рельефом не взаимодействуют.
- У всех акторов сессии один слот текстуры (`texture_count` приходит checkpoint'ом авторитета);
  UI-запросы к акторам по id (`tf_*`) в сессии смотрят в локальный слайс.
- Пока транспорт не признал убитого участника мёртвым (около 10 с), его слот занят, и новички
  получают `no capacity`.
- Причинное содержимое клиента (`causal_content`: разбор модуля, мозги, отпечаток) строится
  синхронно на главном потоке при входе в сетевую сцену — кадр входа заметно длиннее.
- `--frames=N` считает рисованные кадры с запуска, включая загрузку и вход в сессию.
- Срок отчёта растёт с размером checkpoint (64 КиБ/с), а история держит 512 тиков: на очень
  медленном канале снимок может не успеть до выпадения из истории.
